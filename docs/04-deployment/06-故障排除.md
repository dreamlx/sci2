## 开发环境问题

### 问题 1: 数据库连接失败

**症状**: `could not connect to server: Connection refused`

**可能原因**:
- PostgreSQL 容器未运行
- 端口配置错误
- 网络问题

**解决方案**:

```bash
# 检查容器状态
docker ps | grep sci2_test_db

# 启动容器
docker compose up -d

# 检查端口占用
lsof -i :55000

# 查看容器日志
docker compose logs postgres_test

# 进入容器测试连接
docker compose exec postgres_test psql -U sci2_test -d sci2_test -c "SELECT version();"
```

### 问题 2: Ruby 版本不匹配

**症状**: `Your Ruby version is 3.3.0, but your Gemfile specified 3.4.2`

**解决方案**:

```bash
# 检查已安装的 Ruby 版本
rbenv versions

# 安装 Ruby 3.4.2
rbenv install 3.4.2

# 设置本地 Ruby 版本
rbenv local 3.4.2

# 验证版本
ruby -v

# 重新安装依赖
RBENV_VERSION=3.4.2 bundle install
```

### 问题 3: Bundle 安装失败

**症状**: `An error occurred while installing pg`

**解决方案**:

```bash
# 安装 PostgreSQL 开发库
# macOS
brew install postgresql

# Ubuntu
sudo apt-get install libpq-dev

# 重新安装依赖
RBENV_VERSION=3.4.2 bundle install

# 清理缓存
bundle clean --force
RBENV_VERSION=3.4.2 bundle install
```

### 问题 4: Docker 容器端口冲突

**症状**: `Bind for 0.0.0.0:55000 failed: port is already allocated`

**解决方案**:

```bash
# 检查端口占用
lsof -i :55000

# 停止占用端口的进程
kill -9 <PID>

# 或修改 docker-compose.yml 中的端口映射
ports:
  - "55001:5432"  # 使用不同的端口

# 重启容器
docker compose down
docker compose up -d
```

### 问题 5: 测试数据库迁移失败

**症状**: `ActiveRecord::PendingMigrationError`

**解决方案**:

```bash
# 重置测试数据库
RAILS_ENV=test bundle exec rails db:reset

# 检查迁移状态
RAILS_ENV=test bundle exec rails db:migrate:status

# 运行特定迁移
RAILS_ENV=test bundle exec rails db:migrate:up VERSION=20250101000000

# 检查迁移文件
ls -la db/migrate/
```

### 问题 6: macOS + Ruby 3.4 Puma fork 崩溃

**症状**:
```
objc[PID]: +[__NSCFConstantString initialize] may have been in progress in another thread when fork() was called.
We cannot safely call it or ignore it in the fork() child process. Crashing instead.
```

**原因**: macOS 上 Ruby 3.4 与 Puma cluster mode 存在 fork() 安全问题。

**解决方案**:

在 `.env.development` 中添加：

```bash
# macOS + Ruby 3.4 fork 安全问题修复
OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES

# 或禁用 cluster mode
WEB_CONCURRENCY=0
```

### 问题 7: SQLite 迁移后 duplicate key 错误

**症状**: `PG::UniqueViolation: ERROR: duplicate key value violates unique constraint`

**原因**: 从 SQLite 导入数据后，PostgreSQL 的 sequence 没有更新到正确的值。

**解决方案**:

```bash
# 方法 1: 运行迁移脚本（自动重置 sequence）
bash scripts/deploy/import_sqlite_dump_to_pg.sh

# 方法 2: 手动重置单个表的 sequence
docker exec sci2_test_db psql -U sci2_test -d sci2_development -c "
  SELECT setval('reimbursement_assignments_id_seq',
    (SELECT COALESCE(MAX(id), 0) FROM reimbursement_assignments), true);
"

# 方法 3: 重置所有表的 sequence（通过 Docker）
docker exec sci2_test_db psql -U sci2_test -d sci2_development -c "
DO \$\$
DECLARE
    tbl RECORD;
    max_id BIGINT;
    seq_name TEXT;
BEGIN
    FOR tbl IN
        SELECT tablename FROM pg_tables
        WHERE schemaname = 'public'
        AND tablename NOT IN ('schema_migrations', 'ar_internal_metadata')
    LOOP
        seq_name := tbl.tablename || '_id_seq';
        IF EXISTS (SELECT 1 FROM pg_sequences WHERE schemaname = 'public' AND sequencename = seq_name) THEN
            EXECUTE format('SELECT COALESCE(MAX(id), 0) FROM %I', tbl.tablename) INTO max_id;
            IF max_id > 0 THEN
                EXECUTE format('SELECT setval(%L, %s, true)', seq_name, max_id);
                RAISE NOTICE 'Reset % to %', seq_name, max_id;
            END IF;
        END IF;
    END LOOP;
END \$\$;
"
```

## 生产环境问题

### 问题 1: Puma 启动失败

**症状**: `Puma cannot start`

**可能原因**:
- 端口被占用
- 配置文件错误
- 权限问题

**解决方案**:

```bash
# SSH 登录到服务器
ssh deploy@tickmytime.com

# 检查 Puma 配置
cat /opt/sci2/current/config/puma.rb

# 检查端口占用
netstat -tuln | grep 3000

# 手动启动 Puma 查看错误
cd /opt/sci2/current
RAILS_ENV=production bundle exec puma -C config/puma.rb

# 检查日志
tail -f /opt/sci2/current/log/puma.error.log

# 检查权限
ls -la /opt/sci2/shared/tmp/pids/
```

### 问题 2: Nginx 配置错误

**症状**: `502 Bad Gateway`

**解决方案**:

```bash
# 检查 Nginx 配置
sudo nginx -t

# 查看 Nginx 错误日志
sudo tail -f /var/log/nginx/error.log

# 检查 Nginx 状态
sudo systemctl status nginx

# 重启 Nginx
sudo systemctl restart nginx

# 检查上游服务器
curl http://127.0.0.1:3000
```

### 问题 3: 资产预编译失败

**症状**: `Asset precompilation failed`

**解决方案**:

```bash
# SSH 登录到服务器
ssh deploy@tickmytime.com

# 清理预编译资产
cd /opt/sci2/current
RAILS_ENV=production bundle exec rails assets:clobber

# 重新预编译
RAILS_ENV=production bundle exec rails assets:precompile

# 检查 Node.js 版本
node -v

# 检查 npm 版本
npm -v

# 检查磁盘空间
df -h
```

### 问题 4: 内存不足

**症状**: `Cannot allocate memory`

**解决方案**:

```bash
# 检查内存使用
free -h

# 检查进程内存使用
ps aux --sort=-%mem | head

# 减少 Puma workers
# 编辑 config/puma.rb
workers 2  # 减少到 2

# 重启 Puma
RAILS_ENV=production bundle exec puma -C config/puma.rb --daemon
```

## 数据库问题

### 问题 1: 数据库连接超时

**症状**: `could not connect to server: Connection timed out`

**解决方案**:

```bash
# 检查 PostgreSQL 状态
sudo systemctl status postgresql

# 检查 PostgreSQL 日志
sudo tail -f /var/log/postgresql/postgresql-15-main.log

# 检查连接数
psql -U sci2 -d sci2_production -c "SELECT count(*) FROM pg_stat_activity;"

# 增加连接池大小
# 编辑 config/database.yml
production:
  pool: 20  # 增加连接池
```

### 问题 2: 数据库锁死

**症状**: `database is locked` 或查询长时间无响应

**解决方案**:

```sql
-- 查看当前锁
SELECT 
    pid,
    usename,
    pg_blocking_pids(pid) AS blocked_by,
    query AS blocked_query
FROM pg_stat_activity
WHERE cardinality(pg_blocking_pids(pid)) > 0;

-- 终止锁定的进程
SELECT pg_terminate_backend(pid);
```

### 问题 3: 数据库性能问题

**症状**: 查询响应慢

**解决方案**:

```sql
-- 查看慢查询
SELECT 
    query,
    calls,
    total_time,
    mean_time,
    max_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 10;

-- 分析查询计划
EXPLAIN ANALYZE SELECT * FROM reimbursements WHERE status = 'pending';

-- 重建索引
REINDEX DATABASE sci2_production;

-- 更新统计信息
ANALYZE;
```

## 部署问题

### 问题 1: Capistrano 部署失败

**症状**: `Capistrano deployment failed`

**解决方案**:

```bash
# 检查部署配置
bundle exec cap production deploy:check

# 查看部署日志
tail -f log/capistrano.log

# 检查服务器连接
ssh deploy@tickmytime.com

# 检查 Git 仓库
git ls-remote git@gitee.com:dreamlx/sci2.git

# 手动执行部署步骤
bundle exec cap production git:create_release
bundle exec cap production bundler:install
bundle exec cap production rails:db:migrate
```

### 问题 2: SSH 连接失败

**症状**: `SSH connection failed`

**解决方案**:

```bash
# 检查 SSH 密钥
ls -la ~/.ssh/

# 测试 SSH 连接
ssh -v deploy@tickmytime.com

# 检查服务器 SSH 配置
ssh deploy@tickmytime.com "cat ~/.ssh/authorized_keys"

# 重新生成 SSH 密钥
ssh-keygen -t rsa -b 4096 -C "deploy@sci2"
ssh-copy-id deploy@tickmytime.com
```

### 问题 3: 回滚失败

**症状**: `Rollback failed`

**解决方案**:

```bash
# 查看可用版本
ssh deploy@tickmytime.com "ls -la /opt/sci2/releases/"

# 手动回滚
ssh deploy@tickmytime.com
cd /opt/sci2
ln -nfs releases/20250101000000 current

# 重启 Puma
cd current
RAILS_ENV=production bundle exec puma -C config/puma.rb --daemon
```

## 性能问题

### 问题 1: 应用响应慢

**症状**: 页面加载时间长

**解决方案**:

```bash
# 检查应用日志
tail -f /opt/sci2/current/log/production.log

# 检查 Puma 状态
ps aux | grep puma

# 增加 Puma workers
# 编辑 config/puma.rb
workers 4  # 增加到 4

# 重启 Puma
RAILS_ENV=production bundle exec puma -C config/puma.rb --daemon
```

### 问题 2: 数据库查询慢

**症状**: 数据库查询时间长

**解决方案**:

```ruby
# 添加索引
add_index :reimbursements, :status
add_index :reimbursements, [:status, :last_update_at]

# 使用 includes 预加载关联
Reimbursement.includes(:fee_details, :work_orders).all

# 使用 select 只查询需要的字段
Reimbursement.select(:id, :invoice_number, :status)
```

### 问题 3: 内存泄漏

**症状**: 内存使用持续增长

**解决方案**:

```bash
# 检查内存使用
free -h

# 检查进程内存使用
ps aux --sort=-%mem | head

# 重启 Puma
RAILS_ENV=production bundle exec puma -C config/puma.rb --daemon

# 配置 Puma 自动重启
# 编辑 config/puma.rb
worker_timeout 3600
```
